# 界面设计

当前实现是原生 Rust / egui 桌面界面，入口见 [desktop.rs](crates/gui/src/desktop.rs)、[controls.rs](crates/gui/src/desktop/controls.rs)、[appearance.rs](crates/gui/src/appearance.rs) 和 [main.rs](crates/gui/src/main.rs)。产品范围见 [PRODUCT.md](PRODUCT.md)。这里记录实现约定，安装状态和硬件验收另行记录。

## 视觉方向

2026-11-02 改版以可操作的设备工作台为中心：先呈现性能档位，再呈现温度趋势、电池保养、屏幕亮度和常用设备控制。保留磨砂、留白、小尺寸艺术品牌字和不使用蓝色的方向，不再让大标题、诊断说明或不可用的系统电源策略占据首页主体。

宽屏使用左侧导航，窄屏回到可换行的顶部导航。首页的快捷入口使用真实枚举到的接口；不支持的硬件功能不会被装饰卡片伪装成可用功能。历史材质与交互参考包括 [Rauno Freiberg · Designing Depth](https://rauno.me/craft/depth) 和 [Emil Kowalski](https://emilkowal.ski/)，不复制第三方界面或资产。

## 材质、颜色与字体

深色使用带少量橄榄色调的石墨背景，浅色使用象牙白；正文、来源、状态、错误和控件共同使用 `Palette` 中的语义颜色，不为浅色主题复用深色主题的亮色状态文字。

- 深色：背景 `#141614`，面板 `#1F221E`，正文 `#F2F2EA`，次要文字 `#A6AE9E`，标签 `#D4DACD`，强调色 `#BAD697`，警告 `#E4C084`，错误 `#EE9B8C`。
- 浅色：背景 `#F0EFE7`，面板 `#FBFBF6`，正文 `#242A20`，次要文字 `#626B58`，标签 `#424B38`，强调色 `#415F23`，警告 `#855B18`，错误 `#9A2E22`。
- 背景是应用内部生成并按主题缓存的固定柔光纹理，不截取桌面、不调用桌面背景模糊、不随传感器数值闪动。面板使用细边、圆角和轻微高光区分层次。
- [字体资产](crates/gui/assets/fonts/README.md)包含 Cormorant Garamond Italic 和 Manrope 及 SIL Open Font License 1.1；运行时不下载字体。艺术字体只用于品牌，中文由系统字体提供器补全。温度与风扇读数使用真实等宽字体，不把 Manrope 比例数字当作等宽数字。
- 文字缩放范围为 80–160%，有深色、浅色、跟随系统以及可关闭的过渡动画。语义正文在页面、面板和内嵌背景上的对比度有回归测试，最低为 4.5:1；这不等于完整无障碍认证。

## 自适应布局

默认主窗为 1280×900，最小为 360×280，数值均为逻辑单位。整体内容最大宽度为 1440；窗口宽度至少 900 时外边距为 24，否则为 16。

- 窗口可用宽度至少 1180 时显示 172 宽的左侧导航，导航与正文相距 24；更窄时隐藏侧栏并使用顶部导航。正文纵向滚动，顶部保留刷新、自动采样和显示设置。
- 页面为概览、控制、传感器、型号目录。页标题旁显示设备名称、平台和采样来源；长名称省略显示，悬停及设备详情保留原值。模拟数据始终有明确标识。
- 首页首先显示性能与散热档位。卡片按其内部宽度排成五列、三列、两列或单列；阈值分别为 820、480、300。当前运行档位与待选目标分开显示，不能把选中卡片当成已应用。
- 温度面板在内部宽度至少 720 时把 CPU／GPU 读数和真实趋势并排，窄屏上下排列；两组读数在不足 280 时也上下排列。大字体或额外读数允许自然撑高，不裁切内容来维持固定高度。
- 电池保养与屏幕亮度在正文宽度至少 660 时并排，否则上下排列。存在充电接口时优先显示充电模式，系统电源策略放进展开项；没有充电接口时保留系统策略入口。
- Fn 锁、键盘亮度、单区 RGB 等实际枚举到的接口通过快捷入口跳转到控制页，保留目标选择、预览和应用步骤。无接口不生成虚构的控制；暂不可用项显示原因。
- 供电、电池与设备识别信息向下排布。传感器的名称和来源允许换行，可展开全部来源。型号目录只是公开产品信息，不授予控制能力。

首页 CPU／GPU 分别显示同类当前最高的有效温度；悬停可看标签、设备和路径，不据此推断物理热管拓扑。仅当风扇标签明确包含单独的 CPU 或 GPU 名称时才归入对应组；`fan1`、`fan2` 或共享路径不能确定归属。未归属风扇独立呈现，各组最多展示三个并提示省略数量，其余读数在传感器页查看。

## 性能档位与常用控制

Linux 性能桥接仅在厂商为 `MECHREVO`、主板为 `GM6PX0X`，且已安装可信 `/usr/bin/mechrevo-control` 和可读取的 tccd 配置时开放。只接入本机保存的办公节能、游戏低噪、游戏平衡、狂暴性能、全速强冷五档，不猜测其他型号的寄存器、功率或风扇参数。缺失档位不加入选项，重复 ID、自定义活动档位和异常配置拒绝创建写计划。

选择卡片不写硬件。用户先点击“预览档位更改”，确认原值与目标后再点击“应用性能档位”；需要管理员授权。后台重新核对已保存配置、活动配置、tccd 身份和固定控制程序，再调用现有控制器并回读。独立温控保持启用。系统电源策略与这些机械革命档位是不同的控制域。

性能回读确认的是活动配置和已有控制器报告的 EC 模式字节，不保证固定瓦数、持续频率、实体指示灯或风扇 RPM。全速强冷是全速请求，实际转速需看读数；低噪档不承诺具体分贝。配置跨 CPU、风扇和 EC，发生部分失败、后台重启或不一致回读时报告状态未知，不用回写一个旧 ID 冒充完整恢复，也不自动覆盖机身按键的并发选择。应刷新后重新预览。

其他 OEM 控制继续使用经绑定校验的驱动接口。充电项是驱动模式，不承诺固定 60%／80% 阈值；键盘亮度使用实际原始级别，RGB 色块只是目标预览，驱动缓存不等于实体发光测量。屏幕亮度遵守操作系统权限，没有权限时不绕过保护。

## 真实采样与反馈

自动采样默认开启，可关闭。启动时立即提交首次只读刷新，此后距上次成功快照至少 3 秒且条件允许时刷新。已有后台任务、待确认的预览、后台不可用或延后关窗时不自动采样。单个后台任务处理读取和写事务，重复请求不排队堆积。

自动采样开启时显示刚刚更新或采样间隔，关闭后显示“已采集 · 手动更新”，不留下冻结的动态秒数。自动采样空闲时每秒请求重绘，后台忙碌时每 80 ms 请求重绘；这不是每秒读硬件。动画关闭后取消过渡和忙碌图标旋转，状态文字仍可读。

温度历史只保存本次进程的真实采样，每个来源最多 120 点。厂商、产品、主板、BIOS、平台构成机器身份，身份变化清空历史；来源按设备、读数 ID、后端、路径和单位隔离。缺失或非有限值形成断点，不补零、不制造历史。至少三次有效采样才绘制曲线，横轴使用真实采样时间。

当前最高温度来源变化时切换到该来源自己的历史，不拼接不同来源。当前来源缺失时显示“—”，不把历史最后值当成当前值。曲线颜色与 CPU／GPU 标签对应。

## 事务与持久化

预览、显式应用、重新校验和回读在同一事务框架内执行；适用的单项控制保留原有条件恢复。切换目标或手动刷新使已有计划失效；每份计划只使用一次。接口、范围、绑定或原值变化时要求重新预览。写入、回读或必要恢复未结束时延后原生关窗。

OEM 授权仅在显式应用后发生。固定 helper 不接受任意程序、shell、替代 sysfs 根或用户提供的命令路径；性能桥接使用 root 所有且不可由普通用户改写的固定控制器，通过隔离 Python 环境运行。后台等待 helper 的真实退出，不把杀进程式超时视为已取消硬件写入。输出损坏时显示结果未知，禁止自动重放；进程状态也未知时继续阻止新写入和关窗。错误与恢复证据分别保留。

主题、文字缩放、标准／紧凑显示、采样和动画偏好保存在 eframe 用户配置目录，操作计划与温度历史不持久化。紧凑模式仅省去目录收录说明，不强迫缩小控件。

## 验证边界

布局测试覆盖两种主题、五档选择与预览／应用路由、小窗口、大字体、键盘可达性、内容末尾可达性和未知读数。fixture 截图用于布局验收，不作为真实温度或硬件兼容证据。

本次五档桥接已在 GM6PX0X 上通过候选 root 事务逐档切换，独立核对 tccd 活动 ID 和 CPU policy0 的 EPP、频率上下限，结束恢复狂暴模式。它不替代普通用户认证弹窗、GUI 实体按键操作、灯光肉眼检查、噪声、游戏负载或其他机型验收。安装版路径另行核对。

自定义风扇曲线编辑、MUX、水冷和 Windows OEM 后端仍未实现，完整边界见 [OEM 功能覆盖](../docs/OEM-FEATURE-COVERAGE.md)。Windows 编译通过不等于 Windows 硬件已验证。已有 Fn／充电／键盘灯验收见 [OEM 收据](../docs/verification/oem-controls.json)，历史收据不自动覆盖新版本。
