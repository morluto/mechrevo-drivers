# 界面设计

原生 Rust / egui 控制中心。布局在 [desktop.rs](crates/gui/src/desktop.rs)，常用控制在 [controls.rs](crates/gui/src/desktop/controls.rs)，颜色与字体在 [appearance.rs](crates/gui/src/appearance.rs)。功能范围见 [PRODUCT.md](PRODUCT.md)。

## 视觉与布局

界面先显示设备状态，再提供操作：温度与风扇、性能档位、电池保养与屏幕亮度、常用控制、设备详情。数据是主角，诊断细节按需展开。

- 深色采用近黑背景 `#0A0C0E`、深灰面板 `#15181B` 和浅色正文 `#EFF3F5`；浅色采用 `#F4F6F8` 背景与白色面板。
- 薄荷色区分选中状态与 CPU 曲线，琥珀色区分 GPU 曲线。状态同时有文字，不只依赖颜色。两套主题各自定义语义颜色，正文对比度回归门槛为 4.5:1。
- 面板使用 16 圆角与留白，没有背景纹理、阴影或装饰描边。选中与键盘焦点仍有明确标记。
- [Manrope](crates/gui/assets/fonts/README.md) 用于拉丁文字和品牌，中文由系统字体补全。温度与风扇数值使用 egui 等宽字体，避免更新时数字和单位跳动。运行时不下载字体。
- 默认窗口为 1280×900，最小为 360×280，均为逻辑单位。可用宽度至少 1060 且高度至少 440 时显示 184 宽侧栏；否则使用可换行的顶部导航。
- 导航固定在正文滚动区之外。正文宽度不足 480 时，刷新、采样和显示设置移入滚动区，为页面保留空间；其余宽度下这些操作固定在顶部。
- 内容按宽度调整列数：性能档位由五列降至单列；温度读数与曲线、日常控制在窄窗中上下排列。大字体和额外读数可以撑高内容，不裁切来维持固定卡片高度。
- 概览、控制、传感器、型号目录共用导航和设置。长设备名在标题区省略，悬停和设备详情保留全名；来源路径允许换行。模拟数据有明确标识。

## 数据与控制

CPU／GPU 显示同类当前最高的有效温度，曲线显示对应实际来源的历史。历史按机器身份和传感器来源隔离，每个来源最多 120 点；缺失读数形成断点，不补零、不拼接不同来源。至少三次有效采样才绘制曲线，横轴使用采样时间。只有明确标注 CPU 或 GPU 的风扇才归入对应组，通用风扇编号独立显示。

自动采样默认开启。启动时只读刷新，此后距上次快照至少 3 秒且后台空闲时更新；待确认预览期间暂停。关闭后显示“手动更新”。界面重绘与硬件采样是不同频率，关闭动画不会关闭采样。

控制入口来自运行时枚举的接口。性能档位、电池、键盘、屏幕亮度等均保留选择、预览、显式应用与回读步骤。选中目标不代表已应用；不可用项显示原因。型号目录只提供产品资料，不授予控制权限。具体平台与机型边界见 [OEM 功能覆盖](../docs/OEM-FEATURE-COVERAGE.md)。

## 事务与偏好

启动不申请管理员权限。需要授权的操作只在显式应用后请求授权，后台重新核对接口、目标范围、绑定与原值。切换目标或手动刷新会作废计划，每份计划只使用一次。

写入、回读或必要恢复尚未结束时，延后关闭窗口并继续显示状态。失败和结果未知均保留证据，不能把终止等待等同于取消硬件写入，也不能自动重放不确定的操作。

主题、80–160% 文字缩放、标准／紧凑显示、自动采样和动画偏好保存在 eframe 用户配置目录。操作计划与温度历史不持久化。

## 验证边界

[布局回归](crates/gui/tests/headless_layout.rs)检查深浅主题、窄窗、大字体、DPI、长文本、键盘导航、底部可达性、未知读数及预览／应用隔离。测试数据不进入常规启动路径。

软件渲染图用于检查 egui 内容；原生窗口截图用于核对实际窗口与字体。两者都不能证明硬件写入、实体灯光、噪声或其他机型兼容性。改版不扩大后端支持范围，也不替代 Windows 或目标机械革命设备的实机验收。
